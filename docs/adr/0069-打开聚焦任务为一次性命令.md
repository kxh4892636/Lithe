# 打开聚焦任务为一次性命令

`openTaskId` 曾作为粘性的持久期望状态：只有归档或删除任务才清除它。于是
关闭或切换 Agent 面板引发的任务事件（可见任务上报、已读时间更新等）都会让
同步逻辑按它复活并强选旧面板，表现为面板关不掉、切不走；异步启动晚到时
还会回写它抢占焦点。现决定将「打开/聚焦任务」建模为一次性命令：由点击
侧边栏任务、创建、Fork 或打开工具同步发出，中间主界面成功打开并聚焦对应
Agent 面板后立即消费清除；此后关闭或切换面板是有效终态（ADR 0021），任务
事件不再改变界面焦点。异步完成的启动只登记启动结果，不回写选中状态；自动
恢复（ADR 0022）因此也不再影响焦点，启动时的焦点完全由布局快照决定。曾
考虑保留粘性状态并额外记录「用户已关闭」集合，但两个状态源叠加的边界情况
更多；一次性命令与「任务独立于面板存在」的模型一致——面板只是任务的视图。
落地时顺带补齐了会话绑定（bind）的任务变更广播：粘性状态时代的同步循环
反复触发已读上报广播，意外维持了渲染端任务数据的新鲜度；循环撤销后，
绑定完成须由主进程直接推送变更，渲染端才能及时拿到会话标识并选择续接。
