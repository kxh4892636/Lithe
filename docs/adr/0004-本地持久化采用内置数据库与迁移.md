# 本地持久化采用 node:sqlite 与 Drizzle 迁移

Lithe 的运行数据由 main 进程独占，使用 Electron 内置 `node:sqlite` 的 `DatabaseSync` 和 Drizzle `node-sqlite` driver；数据库位于 Electron `userData/lithe.db`。不采用 `better-sqlite3`，从而避免额外原生模块的 Electron ABI 重建和打包负担；同步访问则要求 repository 方法保持短小，未来长耗时工作不能阻塞 main。

数据模型以 `src/main/database/schema.ts` 为事实源，变更后生成并审查 `drizzle/` 中的 SQL migration 与 snapshot，应用启动时自动迁移。数据库启用 WAL、foreign keys、五秒 busy timeout 和 `synchronous=NORMAL`；renderer 只能通过 IPC 使用面向领域的 repository 能力，不能接触连接、Drizzle 对象或 SQL。

已提交 migrations 作为 `extraResources` 随安装产物分发，因此任何 schema 变更既要验证临时真实 SQLite 文件，也要验证跨重启持久化和打包后的 migration 可用性。
