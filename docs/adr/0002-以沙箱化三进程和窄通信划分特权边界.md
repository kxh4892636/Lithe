# 以沙箱化三进程和窄 IPC 划分特权边界

Lithe 将 Electron main、preload 和 renderer 视为单向依赖的安全边界：renderer 只能通过 `window.lithe` 调用 preload 暴露的领域方法，preload 再使用稳定 channel 调用 main。renderer 保持 `sandbox: true`、`contextIsolation: true`、`nodeIntegration: false`，main 拥有 Electron、Node、文件系统和数据库等特权。

跨进程契约与 channel 集中在 `src/shared`，shared 不依赖任一进程实现；新增能力必须按 shared contract/channel、main handler、preload bridge、renderer consumer、tests 的顺序贯通。选择窄而类型化的领域接口，而不暴露通用 `invoke`、`ipcRenderer` 或 Node 对象，是为了限制 renderer 被攻陷后的能力面；代价是每个新能力都需要同步修改多层契约。

main handler 必须校验 sender 和来自 renderer 的外部参数，跨进程值必须可结构化克隆；窗口同时拒绝外部导航、新窗口和 `webview`。
